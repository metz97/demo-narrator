**[DO]** Hover over the eye icon on a specification row, then on an object row.

**[SAY]**
> The eye icon — both on the specification row and on the object row — now uses the same wording: **"Open the associated specification in the Chorus panel"**. Consistent language in both places, so people don't wonder if they do different things.

**[DO]** Hover over an object row status indicator to show the status tooltip. If you can, show two different statuses.

**[SAY]**
> The bigger change is the **association status messages** on the object rows. These used to be very short, and people couldn't tell what they meant. Now each one explains itself, and importantly, each one is phrased as **"at the last refresh"** — because this status is a snapshot, not live data.

> So for example: *"At the last refresh, this object's parameters differed from its associated specification clause. Check the Issues tab in the Chorus Model panel for details."* — that not only tells you the state, it tells you where to go next.

> And when a specification hasn't been checked yet, instead of a blank or confusing state, we say **"Status unknown — refresh the associated specification above to check for updates."**

**[DO]** Trigger a sync / refresh so the result toast appears.

**[SAY]**
> The last piece is the **sync result toast**. This used to use the lazy "(s)" pluralisation — "1 warning(s) and 1 error(s)". Now the message is built dynamically, with correct grammar.

> So it reads "**1 warning and 1 error found**", or "**3 warnings and 1 error found across 4 objects**". If a count is zero, we drop that part completely rather than saying "0 errors". And if everything is fine, it says "**All 4 objects are up to date with their associated clauses**".

> There's also a trailing clause that only appears when it's relevant — *"2 other objects were not checked because they belong to a different specification"* — and it pluralises "specification" properly when more than one is involved.
